# @PROJECT_NAME@

A C++20 Connect RPC client and server generated by `connectcpp new`.

```sh
connectcpp build
./build/greeter serve
# In another terminal:
./build/greeter call http://127.0.0.1:8080 Ada
```

On Windows, run `build\greeter.exe` from a developer terminal.
The build runs a real loopback client/server test (`ctest --test-dir build`).
Stop the server with Ctrl+C; it drains connections before exiting.

Edit `proto/greet/v1/greet.proto` and the handler in `src/main.cc`, then rebuild.
CMake regenerates the Protobuf messages and typed Connect bindings automatically.
List schemas with services under `SERVICES`; list message-only imports under
`MESSAGES` in `connectcpp_generate`. Do not edit generated files.

With the full Protobuf SDK, try the JSON endpoint (Lite supports binary messages
only):

```sh
curl --header 'Content-Type: application/json' \
  --header 'Connect-Protocol-Version: 1' \
  --data '{"name":"Ada"}' \
  http://127.0.0.1:8080/greet.v1.GreetService/Greet
```

This development example listens on loopback with cleartext HTTP/1.1. For remote
services use verified TLS. For bidirectional streaming use HTTP/2 throughout.
Keep the event loop and handler alive until all calls and shutdown tasks finish.

This is an ordinary CMake project; the CLI only supplies your installed SDK's
paths. It does not pin your SDK automatically. Record a Connect C++ revision and
dependency baseline for CI, and use a matching compiler and Protobuf runtime.
See https://github.com/happenings-dk/connect-cc/blob/main/docs/INSTALLATION.md.
